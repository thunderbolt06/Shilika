## 0. Headline findings (ranked)

1. CRITICAL - The JSON-LD is not in the server-rendered HTML on ANY page. 0 `<script type="application/ld+json">` elements in raw HTML on all 26 live pages, including when fetched with GPTBot, ClaudeBot, PerplexityBot and Googlebot user agents (identical byte size). It only exists inside the Next.js RSC flight payload (`self.__next_f.push`) and is injected into the DOM after hydration. Crawlers that do not execute JS (most AI retrieval bots, curl-based validators, many LLM ingestion pipelines) see no structured data at all. All 250+ pages use `next/script` `<Script>` instead of a plain `<script>` tag.
2. HIGH - Duplicate, conflicting entities. Two Person @ids (`/#person` and `/authors/shilika-jain`) and two Organization @ids (`/#organization` and `/#org`) for the same human and practice. The ~314 blog posts and the author page use the second set; everything else uses the first set. Nothing joins them.
3. HIGH - Price claims contradict each other, including inside one JSON-LD block. Offers say $5,000-$12,000 per month, the FAQ text in the same block and the visible page say $3,000-$7,000, the homepage meta and hero say $5k-10k, the /faq page says $5K-$14K.
4. HIGH - Self-serving review markup: `aggregateRating` (5.0, 19 reviews) and 4 five-star `Review` objects on a `Person` (invalid property for Person in schema.org). LinkedIn recommendations carry no star rating, so the 5s are manufactured.
5. MEDIUM - The repo's FAQ parity script reports "0 defects" but only compares question text. Answer text differs materially on the 8 /services pages (33 of 95 schema answers share less than 60 percent of their words with the visible answer; 47 of 95 under 90 percent).
6. MEDIUM - Locale pages (zh, ko, ja, es, ru) carry only a thin WebPage/Article stub, declare `<html lang="en">` in server HTML, and have dangling `translationOfWork` @ids.
7. MEDIUM - Systematic schema.org vocabulary errors generated by the templates (`unitText` on PriceSpecification in 112 partials, `inLanguage` on Service in 106 partials, `provider`/`serviceType`/`audience` on ProfessionalService, `aggregateRating`/`review`/`workExample` on Person).
8. LOW-MEDIUM - dateModified is missing on all service pages, stale on the homepage, and inconsistent with the visible "Updated" label on Japan.

Strengths: every one of the 253 JSON-LD partials is valid JSON, FAQ question parity is exact on every tested page, all sameAs URLs resolve, canonicals and hreflang are correct, titles/descriptions are unique, BlogPosting markup is complete, `@graph` + `@id` architecture is a sound design.

## 2. CRITICAL: JSON-LD is not in the initial HTML

Evidence, raw HTML (curl):
```
_about.html   ld+json script tags=0   '@type' occurrences in raw html=78
_.html        ld+json script tags=0   '@type' occurrences in raw html=70
... (same pattern on all 26 pages; the '@type' hits are escaped strings inside self.__next_f.push payloads)

UA=GPTBot/1.1        status=200 size=122973  ld+json script tags: 0
UA=Googlebot/2.1     status=200 size=122973  ld+json script tags: 0
UA=ClaudeBot/1.0     status=200 size=122973  ld+json script tags: 0
UA=PerplexityBot/1.0 status=200 size=122973  ld+json script tags: 0
```
Evidence, rendered DOM (browser, after hydration):
```
/about                              -> 1 x <script type="application/ld+json" id="about-jsonld"> in HEAD (11264 chars)
/                                   -> 1 x id="homepage-jsonld" in BODY (25337 chars)
/services/web3-pr-campaigns         -> 1 x id="services-web3-pr-campaigns-jsonld" in HEAD (15109 chars)
/authors/shilika-jain               -> 1 x id="author-jsonld-shilika-jain" in HEAD
/zh                                 -> 1 x id="i18n-jsonld-home" in BODY (528 chars), html lang flips en -> zh-Hans only after JS
```
How it appears in the raw HTML: `...{"id":"homepage-jsonld","type":"application/ld+json","dangerouslySetInnerHTML":{"__html":"$6"}}...` plus a later `n6:T62fa,` text chunk holding the JSON. That is flight data for React hydration, not a parseable JSON-LD element.

Cause: `next/script` (`<Script type="application/ld+json" strategy="beforeInteractive">`) in page components. `beforeInteractive` is only honoured in the root layout in the App Router, and `next/script` does not server-render inline scripts. Next's documented pattern for JSON-LD is a plain `<script type="application/ld+json" dangerouslySetInnerHTML=...>` rendered in the server component.

Impact (what is verified vs not):
- Verified: zero parseable JSON-LD for any client that does not run JS.
- Unverified: whether Google's renderer picks it up (it normally executes JS, so probably yes) and which AI crawlers execute JS. Treat the entity layer as invisible to non-rendering AI crawlers until fixed.
- Contrast: microdata FAQ blocks ARE in server HTML (`/faq` has 11 Question/Answer + 1 FAQPage microdata items in raw HTML, `/zh`, `/ko`, `/ja`, `/es`, `/ru` home pages 12 each). So the only schema non-JS bots can read today is the homepage-locale and /faq microdata.

Fix: render JSON-LD with a plain `<script>` tag. About 250 page.tsx files plus 3 dynamic routes (`blog/[slug]`, `authors/[slug]`, `[locale]/[[...path]]`). It is a mechanical codemod. Verify with: `curl -s URL | grep -c 'application/ld+json'` expecting >= 1.

# Shilika site — Next.js + Supabase setup

This file covers Phase 1 setup. Phases 2–5 add admin tools, content pipeline, cron jobs.

## 1. Rotate the leaked Supabase secret first

The `sb_secret_…` key that was pasted in chat must be rotated **before any deploy**.

- Open the Supabase dashboard for project `yzgaxyxoosazxfnsyqta`
- Project Settings → API → click **Roll** on the `service_role` (secret) key
- Copy the new secret into `.env.local` (see step 3) and into Vercel env vars (step 6)
- Do **not** commit `.env.local`

## 3. Local environment

Copy the template and fill in the new secret + a long random `ADMIN_PASSWORD`:

```bash

```

Required for Phase 1:
- `NEXT_PUBLIC_SITE_URL` — `http://localhost:3000` locally, `https://www.shilikajain.com` on prod
- `NEXT_PUBLIC_SUPABASE_URL` — `https://yzgaxyxoosazxfnsyqta.supabase.co`
- `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` — the `sb_publishable_…` key (safe to expose)
- `SUPABASE_SECRET_KEY` — the **rotated** `sb_secret_…` key

Used in later phases:
- `ADMIN_PASSWORD`, `ADMIN_SESSION_SECRET` (Phase 3 admin)
- `ANTHROPIC_API_KEY`, `GOOGLE_GENAI_API_KEY` (Phase 4 writer + image gen)
- `CRON_SECRET` (Phase 5 cron auth)
- `GSC_*` and `GA_*` (Phase 5 analytics feedback loop)

## 4. Apply database migrations

Three SQL files in `supabase/migrations/`:
- `0001_blog_foundation.sql` — tables for `blog_posts`, `content_ideas`, `authors`, `knowledge_base`, `analytics_search_console`, `content_metrics`, plus indexes, RLS, and triggers
- `0002_storage_bucket.sql` — `media` bucket for hero images + screenshots
- `0003_seed_author.sql` — seeds Shilika as the default author

Two ways to apply them:

**Option A — Supabase Dashboard SQL editor (fastest one-time):**
Open each file, copy its contents into the SQL editor, run.

**Option B — Supabase CLI (best for ongoing migrations):**

```bash
npm i -g supabase
supabase link --project-ref yzgaxyxoosazxfnsyqta
supabase db push
```

## 5. Local dev

```bash
npm run dev
```

Open http://localhost:3000 — the homepage is the ported `index.html` rendered through the Next.js
App Router. `/blog` lists published posts (empty until Phase 3 seeds the three blog templates).

Useful routes during Phase 1:
- `/` — homepage
- `/blog` — empty playbook index
- `/blog/[slug]` — single post renderer (will 404 until rows exist)
- `/api/markdown/blog/[slug]` — AI-bot-friendly markdown alternate
- `/sitemap.xml`, `/robots.txt` — generated by Next.js
- `/about`, `/services/*`, `/work/*`, `/article-*` — still served from `public/*.html`. Phase 2 ports them to Next.js routes.

## 6. Vercel project setup

Once you deploy, set these env vars in Vercel → Project Settings → Environment Variables. Mark each
as **Production** + **Preview** + **Development** unless you want preview to point at a different DB.

```
NEXT_PUBLIC_SITE_URL=https://www.shilikajain.com
NEXT_PUBLIC_SUPABASE_URL=https://yzgaxyxoosazxfnsyqta.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=sb_publishable_-Kv3Pdefiz7CxwBKM1wZJw_WG3Tiav0
SUPABASE_SECRET_KEY=<the new rotated secret>
```

Vercel auto-detects Next.js. The previous `vercel.json` (static-only headers) has been replaced
with a minimal config — security headers + cache-control now live in `next.config.ts`.

## Phase plan recap

- **Phase 1 (this PR)** — foundation: Next.js scaffold, Supabase schema + clients, blog read routes, dual format, sitemap/robots, homepage port
- **Phase 2** — convert all remaining HTML pages (services/*, work/*, articles, about, testimonials) to native Next.js routes, drop the rewrites
- **Phase 3** — `/admin` password gate, Excel upload/download (xlsx upsert by id), knowledge base CRUD, 3 seed SEO blog templates (Web3 PR / embargo / crisis comms)
- **Phase 4** — Gemini Nano Banana image generation, humanization validator, writer agent (Claude API), review queue at `/admin/blog/review`
- **Phase 5** — Vercel cron + Background Functions: queue filler, daily writer, hourly publisher, GSC + GA pulls, weekly SEO brief, topic-research agent that mines long-tail phrases
